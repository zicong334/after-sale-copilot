## W9-1 VectorBackend 真实现(本机形态)

- `retrieval/vector_backend.py`:sklearn `TfidfVectorizer`(char_wb+word ngrams 混合,中文友好)→ `TruncatedSVD`(dim=64,random_state 固定)得稠密向量;L2 归一化后存新表 `kb_vector`(迁移 0007:knowledge_item_id UNIQUE + vec BLOB + model 名 + dim);余弦相似度 top-k。
- 确定性:拟合语料=当前 active 条款集;SVD 随机种子固定;重建时机=load_policies/KB 热更新时(与 BM25 同生命周期)。
- `VectorBackend` ABC 由本实现 fulfill(删 NotImplementedError 分支,保留 ABC 供 pgvector/Milvus 缝,注释标明)。

## W9-2 双路 RRF 融合 + 停用词 + rerank

- `HybridRetriever`:BM25 top-20 与 vector top-20 → RRF(k=60)融合 → 电商停用词表(guardrails 或 retrieval 常量:怎么/弄/一下/请问/吗/呢/我/想/帮/看看 等 ≥30 词)在 tokenize 前清洗(**查询侧与索引侧同用,索引重建**)→ 重叠度 reranker(query 与 clause 的关键词 jaccard+clause_id 先验)取 top-5,threshold 语义改为融合分阈值,定标重写进 docstring(数字可复算)。
- 定标验收:≥10 句表(含已知局限句"我想退钱怎么弄"、"退差价怎么算"、原 8 句不回归),贴修复前后分数对照;重噪声句必须命中正确 clause。

## W9-3 知识库管理后台 API

- `/api/kb`(agent role 鉴权,沿用 W8 RBAC):条款 CRUD、status(draft/active/retired)灰度、版本自增、`POST /api/kb/reload` 热更新(重建 BM25+vector 不重启)、`POST /api/kb/upload`(md 文本→自动切片成条款草稿)、退役条款检索不可见但可回滚(`POST /api/kb/{id}/restore`)。
