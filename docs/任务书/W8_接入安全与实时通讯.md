## 五项落地

### S1 JWT 鉴权 + RBAC(消灭明文身份)
- `POST /auth/login {username, password}`:seed 增加账号表迁移 0006_auth(user: id/username/password_hash(pbdkdf2 或 argon2 纯标准库实现)/role=buyer|agent/绑定 customer_id 或 service_id/merchant_id);密码仅存哈希,seed 里演示账号明文写进 README"演示账号"节。
- 签发 HS256 JWT(secret 走 env `JWT_SECRET`,缺省 dev 值并打 MOCK 级警告日志);payload:sub/role/customer_id|service_id/merchant_id/exp(2h)。
- 中间件:`/api/c/*` 需 buyer token,`/api/b/*` 需 agent token,`/auth/*`、`/health`、`/metrics`(若有)、静态资源放行;**身份一律从 token 解析**,chat/handoff/confirm/agent 各路由删除请求体/query 里的 customer_id/service_id 入参(改为 ctx 注入);前端 app.js/agent.js 改登录流程(localStorage token,401 跳登录)。
- 登录页 `frontend/login.html`(视觉令牌同系;演示账号一键填入按钮)。
- 测试:无 token 401、错 role 403、过期 401、篡改签名 401、身份从 token 来(请求体带别人 id 无效)。

### S2 限流防刷
- 进程内令牌桶:`RateLimiter` ABC + `MemoryRateLimiter`(用户级 5 QPS 突发 10、租户级 50 QPS;chat 接口另计日 token 配额,从 usage 聚合,超限 429+`Retry-After`);配置常量进 guardrails 或独立 config 模块。
- 测试:连发超桶→429 且 Retry-After 存在;配额计数正确。

### S3 写接口防重放
- confirm/reject/claim/close/reply 五个写接口要求头 `X-Timestamp`+`X-Nonce`:窗口 ±5 分钟、nonce 表(unique+TTL 清理)重放拒 409/401;前端 fetch 统一加头。
- 测试:重放同 nonce 被拒;超窗被拒;缺头 400。

### S4 WebSocket 双向实时
- `PubSubBroker` ABC + asyncio 内存实现;频道 `buyer:{session_id}`、`agent:{service_id}`、`queue:{merchant_id}`。
- 端点 `/ws/buyer`(token 查询参数或首帧鉴权)、`/ws/agent`;事件:agent 回复到达、工单状态变更、队列新增、确认卡状态;chat/agent 路由在写库后 publish。
- 前端:WS 主通道,断线自动回退现有轮询(保留轮询代码路径);工作台队列实时刷新。
- 测试:TestClient websocket_connect 双端收事件;断线降级轮询仍工作。

### S5 CORS 收敛
- allow_origins 配置化(env `CORS_ORIGINS`,默认 `http://127.0.0.1:8000,http://localhost:8000,http://127.0.0.1:8033` 等本地三端口),删除任何 `*`。
