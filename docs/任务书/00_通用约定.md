# 任务书通用约定(所有 dsh 会话必须遵守)

> 每份任务书开头写"先读本文件"。本文件 + 具体任务书 = 该会话的全部要求。

## 1. 项目根与环境

- 项目根 ROOT = `D:\科研工作台\10_归档封存\点头直通车项目\售后 Copilot`(下文相对路径都相对 ROOT)
- Python 只用 ROOT 下 `.venv`(Python 3.13):测试命令一律 `ROOT\.venv\Scripts\python -m pytest …`,禁止用全局 python/pip 装任何包
- 依赖以 `requirements.lock.txt` 为准;需要新依赖时**不要自行安装**,在回执里写"申请新增依赖:包名+理由",由主会话决定
- 操作系统 Windows,shell 可能是 bash 或 PowerShell;脚本要能在 Windows 跑(路径用 `pathlib`,不硬编码 `/`)

## 2. 红线(违反任何一条 = 验收不通过)

1. **只写白名单文件**:每份任务书列出的"产物文件"之外,不得创建/修改任何文件(尤其不得改 `docs/`、`progress.md`、其他任务书的产物)
2. **归档只读**:`ROOT` 之外的一切(尤其 `点头直通车项目\` 下其他 13 个子项目)只读——可以按任务书给的路径:行号去读参考代码,不得写入、不得在其中运行任何东西
3. **禁止假实现**:不允许 mock 冒充真实实现;确实需要 mock 的地方(如 FakeLLM)必须在代码注释和回执里显式标注 `MOCK`;`grep TODO/FIXME/NotImplemented/pass  # stub` 的结果会作为验收证据
4. **数字可复算**:回执里的测试通过数、覆盖率等一切数字,必须能由回执附带的原始命令输出重算;对不上 = 验收不通过
5. **不碰 git**:不 init、不 commit、不改 .gitignore(由主会话统一做)
6. **金额整数分、时间 UTC、状态有 CHECK**:数据层三铁律,任何新表/新字段都适用

## 3. 上下文纪律(防卡死,来自上次事故)

- 读大文件用分段读(如 `sed -n '100,200p'`),单次工具输出控制在 200 行内
- 单个产物文件超过 ~400 行就拆多个模块文件写
- 感觉上下文吃紧时,先把当前进度写成 `ROOT/backend/_draft_<任务号>.md` 工作稿再继续(收尾时删除工作稿)
- 不要一次性读完参考项目;任务书给了"只需读这几段"的清单,照单读

## 4. 回执格式(会话最后一条消息,必须包含全部五项)

```
【产物清单】逐个文件:路径 + 行数 + 一句话说明
【测试证据】完整命令 + 输出末尾 ≥20 行原文(含通过/失败计数)
【验收自检】对照任务书"验收标准"逐条:标准原文 → 通过/不通过 → 证据(命令输出或 路径:行号)
【未尽事项】没做完的、降级的、申请新增依赖的;没有就写"无"
【progress 素材】一行:`<任务号> | 做了什么(commit 由主会话打) | 测试 x passed | 遗留`
```

## 5. 失败与阻塞处理

- 同一报错的自愈受 §7.3 熔断约束(**最多 2 次重试**);熔断跳闸、或遇环境权限/依赖冲突/未定义契约 → 停下来,按 §7.3 的 Block 报告格式汇报,不要绕路硬做
- 发现任务书之间有矛盾、或任务书与 PRD 矛盾 → 停下来汇报,以 `docs/PRD_v1.md` 为准
- 验收标准达不到但认为已尽力 → 照实回执"不通过+原因",**禁止把失败洗成成功**

## 6. Windows 沙箱环境护栏(W1-A 首次派发用 80 个残留临时目录换来的教训,必须遵守)

1. **临时目录只用 ROOT 下的 `.tmp/`**:任何要跑 python/pytest 的命令,前缀 `TMP="$PWD/.tmp" TEMP="$PWD/.tmp"`(先 `mkdir -p .tmp`);系统临时目录可能被沙箱拦,被拦时**不许**在项目根建探针文件(`_probe*`、`_abs_test*` 之类)或调 pwsh 诊断脚本自修——直接在回执汇报"沙箱挡了哪里"。**点名禁令(两次卡死事故的元凶,2026-11-07 W1-A/W4-B)**:严禁调用 `diagnose-windows-sandbox-acl` 或任何诊断类 skill;严禁运行 `powershell.exe`/`pwsh`(会挂死整个会话);pytest `--basetemp` 每次用全新唯一目录(如 `.tmp/pytest_<任务号>`),不复用旧目录(残留 ACL 会触发权限错误)
2. **pytest 固定姿势**:`.venv\Scripts\python -m pytest backend/tests -q -p no:cacheprovider --basetemp=.tmp/pytest`(不产生 pytest-cache-files-* 泄漏,tmp 文件集中可清理)
3. **alembic 固定姿势**:`.venv\Scripts\python -m alembic -c backend/alembic.ini upgrade head`(url 已指向 backend/dev.db;dev.db 可随时删,不进 git)
4. 测试代码里需要临时文件时,一律用 `tmp_path` fixture(配合 --basetemp)或显式建在 `.tmp/` 下并在 teardown 清理;**禁止** `tempfile.mkdtemp()` 裸用(默认落系统 temp,沙箱下会泄漏到项目根)
5. 收尾前自查:`ls -a ROOT` 里不许有白名单和 `.tmp/`、`.venv/`、`backend/`、`data/`、`frontend/`、`docs/`、`.git*`、`requirements*`、`serve*`、`run_eval*` 之外的东西

## 7. 次模执行守则(高吞吐低消耗基线,2026-11-07 用户提供模板整合,对所有会话生效)

> 核心逻辑:把"发散思考"剥离,只保留"机械执行"与"结构化闭环"。轻量模型最易在上下文过长、指令模糊、报错自愈时反复空转——以下三组约束分别封死这三个漏洞。

### 7.1 通用守则(常驻基线)

1. **确定性第一**:严格按任务书逐项打勾执行;不自作主张新增"优化项"、不顺手重构既有逻辑、不对架构方案提出异议(有不同意见写进回执"未尽事项",由主会话裁决)
2. **最小变更(Minimal Diff)**:只改实现产物必须触碰的代码;不顺手调整未分配文件的格式、缩进、命名、注释
3. **纯净输出**:不寒暄、不复述任务、不输出长篇实现思路或设计理由;直接执行工具调用,只给结构化改动结果+简要说明
4. **阻断即上报**:遇环境权限、依赖冲突、未定义契约,就地保留现场并出 Block 报告(§7.3 格式),严禁自行尝试多种旁门左道

### 7.2 编码落地(配合 §2 白名单红线)

- 文件白名单是硬边界:严禁触碰范围外既有文件;严禁改 requirements.txt / requirements.lock.txt 等公共依赖(新依赖走回执申请)
- 禁止引入任务书未显式允许的第三方库
- 产出代码必须完整可运行:严禁省略号占位(`// ... 保持原有代码不变 ...`)、严禁空壳 stub(与 §2 红线 3"禁止假实现"一致)

### 7.3 验证与排障(熔断自愈)

1. **调试循环只跑最小化测试**(如 `pytest backend/tests/test_x.py -k 关键字`);**全量测试只在收尾交回执前跑一次**——全量绿是验收硬项,不可省,但也不许每改一行就全量跑(本工程全量约 80-130 秒,是最贵的空转源)
2. **输出纪律**:成功只报 PASSED+耗时;失败只取 traceback 末尾 20 行,严禁把完整长日志灌回会话上下文
3. **熔断机制(Max 2 Retries)**:同一报错最多 2 次自行修改代码并重跑;第 2 次仍不过 → 立即中止,按以下格式写进回执(与既有"已试/未试/推荐"合并):
   - `[Root Cause Analysis]` 为什么两次修改未能奏效
   - `[Observed Behavior]` 实际报错与预期差异(附关键输出原文)
   - `[Blocker]` 需要主会话/人工介入确认的关键点
   - `[已试/未试/推荐]` 三段
