## W11-1 OrderItem 部分退款折算

- 迁移 000x_refund_items:`refund_item`(refund_request_id FK / order_item_id FK / qty / unit_cents / line_cents),退款单总额=Σ line_cents,服务层校验 ≤ 订单实付残额(实付-已退);同一 order_item 累计退 qty ≤ 购买 qty。
- `refund__create` input 增可选 `items:[{order_item_id, qty}]`:不传=整单退(旧行为不变,回归保护);传则按子项折算金额,**忽略调用方传的 amount_cents**(服务端计算,防篡改;schema 里 amount_cents 变可选并标注)。
- 幂等键扩展:含 items 摘要哈希。
- 测试:部分退金额核算/超残额拒/超qty拒/整单旧路径不回归/幂等键含子项。

## W11-2 退货物流与验货回调状态机

- order/refund 状态扩展(迁移同包):refund_request.status 增 `退货中`(审核通过后买家填物流)→`待验货`(物流单号回填)→`退款`(验货通过回调)/`驳回`(验货拒);状态迁移表写进模型 docstring+测试。
- 买家端 `POST /api/c/refunds/{id}/shipping`(buyer token):填 `tracking_no`(格式校验)→ 状态 退货中→待验货,守卫式。
- 仓库回调 `POST /api/fulfillment/inspection`(HMAC 签名头 X-Signature=sha256(body+secret),secret 走 env `FULFILLMENT_SECRET`,dev 默认值+MOCK 标注):{refund_id, passed:bool, reason} → passed=真→审核/待验货→退款 并触发 order 守卫式 refunded(仅当全单退完);passed=假→驳回+工单摘要更新。重放同请求体+nonce 拒。
- 测试:状态机全迁移+非法迁移拒+签名错 401+重放拒+部分退不触发 order.refunded(残额>0)。
