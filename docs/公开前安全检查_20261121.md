## 11. 用户裁定:邮箱不公开,其余都可以(2026-11-21)

### 为什么必须改写历史

GitHub 的 "Keep my email addresses private" 设置**不追溯抹掉已有提交里的邮箱** ——
commit 对象本身就带着它,clone 后 `git log` 与 patch 视图都能看到。
所以要真不公开,**只能改写历史**,开设置不够。

### 做法(保守 + 可回退)

1. **先建可校验的完整备份**:
   ```bash
   git bundle create .tmp/history_backup/before_email_scrub.bundle --all
   git bundle verify .tmp/history_backup/before_email_scrub.bundle
   # → "The bundle records a complete history."(6.4 MB,含所有 ref)
   ```
2. **只改邮箱,别的一律不动**:
   ```bash
   FILTER_BRANCH_SQUELCH_WARNING=1 git filter-branch -f --env-filter '
   NEW="209721848+zicong334@users.noreply.github.com"
   case "$GIT_AUTHOR_EMAIL" in zicong@mails.ccnu.edu.cn|zicong@local) export GIT_AUTHOR_EMAIL="$NEW";; esac
   case "$GIT_COMMITTER_EMAIL" in zicong@mails.ccnu.edu.cn|zicong@local) export GIT_COMMITTER_EMAIL="$NEW";; esac
   ' --tag-name-filter cat -- --all
   ```
   **作者名、提交信息、日期、提交结构全部保留** —— 四轮审计的逐棒留痕是作品集最有价值的部分,不能丢。
3. **本仓 `git config user.email` 设为 noreply**(未来提交不再带进来);
   **未改全局配置**,其他仓不受影响。

### 验证(原始输出)

```bash
git log --branches --tags --format="%ae %ce" | grep -E "ccnu|@local"
# → 空(可推送 ref 上旧邮箱已清除)

git log --branches --format="A:%an <%ae>%nC:%cn <%ce>" | sort -u
# → A:zicong <209721848+zicong334@users.noreply.github.com>
#   A:zicongzhu <209721848+zicong334@users.noreply.github.com>
#   (committer 同)
```
提交数 109、工作树干净、标签 `v0.9-second-round` 已随 `--tag-name-filter cat` 一并重写。

### 过程留痕:第一次改写被拒

首次 `filter-branch` 输出 **"Cannot rewrite branches: You have unstaged changes"**
(`progress.md` 有未提交的 CI 发现记录)。**核身份清单发现没变**才确认是拒绝而非成功 ——
那条复合命令的退出码被末尾 `tail` 掩盖了。先提交进度,再重跑才成功。
**教训:改写类操作必须回读结果验证,不能只看退出码。**
