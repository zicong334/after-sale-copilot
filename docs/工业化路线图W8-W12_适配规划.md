# 工业化路线图 W8-W12:七层补齐的本机适配规划(主会话,2026-11-09)

> 输入:用户提供的"大厂七层架构"清单(W8-W12 五包)。原则:**每层给"本机真跑形态 + 生产缝(接口+配置开关)"**,禁止假实现;本机跑不了的环节,交付物是代码路径+配置+文档,并显式标注"本地替身",简历与 README 不许把替身说成产线组件。
> 本机底座实测(2026-11-09):无 Docker、无 Redis、无 PostgreSQL、无 WSL;16 核;Python 3.13 venv;SQLite WAL。用户 key 限定 deepseek-flash 单模型。

## 0. 总纪律

1. 每包=一份任务书+一个 dsh 会话(必要时拆两个)+主会话亲测验收;Fake 密封,真实 API 零新增花费(路由/缓存演示用 stub)。
2. 所有"生产缝"=Python 协议类(ABC)+ 配置项 `BACKEND_*`(如 `BACKEND_BROKER=memory|redis`),本机默认 memory/sqlite 实现,redis/pg 实现允许只到"代码+单测用 fakeredis 风格 stub"或仅配置文档,标注清楚。
3. 多 Worker 安全论述要诚实:我们的 confirm/claim 并发安全**本来就靠 DB CAS+幂等键**(跨进程有效),进程内锁只是快路径;W8 起把 per-token 锁换成 DB 行锁/条件更新,消除"多 worker 失效"的真实部分。
4. 评测集/迁移纪律不变;每包收尾全量测试+check_w1+smoke 不倒退。

## 1. W8 接入安全与实时通讯包
