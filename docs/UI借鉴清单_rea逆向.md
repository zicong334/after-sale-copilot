# UI 借鉴清单(来源:rea_web_test 逆向资料,2026-11-11 主会话评估)

> 资料实况:REA 报告主体是**技术栈指纹与工具链经验**(React/Pegasus/mtop、Nuxt SSR、jQuery 多页),直接可抄的 UI 设计规范有限;真正可借鉴的是 T4 淘宝首页实拍截图的视觉惯例 + 电商售后通用模式(退款进度条)。另有两条我们已对齐,一条不采纳。

## 采纳(进 W15 前端精修包)

| # | 借鉴点 | 来源 | 落到安心退哪里 |
|---|---|---|---|
| U1 | **售后进度 stepper**(申请→审核→退款/驳回 纵向时间线,当前节点高亮+时间戳) | 淘宝退款详情页通用惯例 | 买家回执卡下方 + 工作台工单详情"处理进度"区;数据源=refund_request.status/decided_at(B2 已补 refund_request_id) |
| U2 | **价格红橙药丸徽标**(¥+大号数字压在卡片图上/右下角,白字红底) | 淘宝首页商品卡实拍(¥13390/¥8212 徽标) | 买家订单卡、工作台工单详情的金额展示;沿用暖色令牌系(主色 #C05621 变体) |
| U3 | **状态角标**(卡片右上彩色小标签:新品推荐/省钱 样式) | 同上 | 工单队列卡:待领取/跟进中/待客户回复/已关闭 四状态角标化(替代纯文字徽章) |
| U4 | **图标+文字胶囊快捷入口** | 淘宝类目 chips(图标+词) | 欢迎屏三快捷词加 SVG 小图标(复用现有角色 SVG 画法) |

## 已对齐(无需动)

- 队列新消息差量计数徽章 ↔ 淘宝 `im.message.unreadcount` 模式(W14 已实现)
- 登录覆盖层/扫码切换——我们是独立登录页+演示账号一键填入,规模合适,不抄弹窗

## 不采纳(及理由)

- 右侧悬浮工具栏(客服/购物车 icon rail):单页 demo 无多页导航需求,徒增复杂度
- SSR+水合、mtop RPC、风控三件套:架构级不匹配单机形态;我们的等价物已是 W8 鉴权+限流+防重放+guardrails

## 对 REA 资料本身的一句话评价

工具链经验(超时先查 Evidence 再下结论、排除法定位病态文件、预标注只当线索)与我们"亲测不采信回执"的验收纪律同构,可写进《架构反思》作旁证;技术栈结论对本项目无直接改造价值。
